How the Optimizer Works

1. Courses as a Directed Acyclic Graph (DAG)

Each course is a node. An edge A → B means A is a prerequisite of B. Before a prerequisite is added, the app checks whether B can already reach A. If it can, the link would create a cycle that can never be completed, so it is rejected.

2. Topological Sorting (Kahn's algorithm): O((V+E) log V)

The algorithm repeatedly takes a course whose prerequisites are all done, then unlocks the courses that depend on it. The result is always a valid order.

3. Min-Heap for prioritisation: push/pop O(log n)

A hand-written binary min-heap holds the courses that are available right now. Kahn's algorithm pops the best one: highest rating, highest popularity, or shortest duration. Values where higher is better are negated, because it is a min-heap. The same heap powers Recommend.

4. Dynamic Programming on the DAG: O(V+E)

Courses are processed in topological order, so every prerequisite is solved before the course itself.
• Longest path: finish(v) = duration(v) + max(finish(prereqs)) gives the minimum time to finish everything when courses are taken in parallel.
• Shortest path: dist(w) = min(dist(v) + duration(w)) gives the quickest route between two courses.

Why this minimises total time

Taking courses one at a time, every valid order adds up to the same number of hours. Time is saved by (a) taking only the prerequisites needed for your goal (Goal Planner) and (b) studying independent courses in parallel (Fastest Finish).
